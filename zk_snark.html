zk-SNARK State Publishing in Ethereum L2

How zk-rollups prove state validity on Ethereum

zk-Rollup State Publishing Flow
1
Execute Off-Chain
Transactions are executed on Layer 2, processed off the main Ethereum chain for speed and cost efficiency.
Off-chain execution
2
Compute State Root
Layer 2 computes a new state root/commitment representing the updated state.
State commitment
3
Publish Data
Compressed transaction data is published to Ethereum for data availability.
Data availability
4
Submit zk-SNARK Proof
A cryptographic proof is submitted to verify the correctness of the state transition without revealing the data.
Validity proof
5
Verify & Accept
Ethereum smart contract verifies the proof before accepting the new state.
Verified
Key Difference from Optimistic Rollups
zk-rollups prove correctness upfront with cryptographic validity proofs, while optimistic rollups rely on fraud proofs and require a challenge period (typically 7 days) before finalizing transactions.
